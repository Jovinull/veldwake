# Reusable learnings

Last updated: 2026-09-21

- On the audited Windows host, PowerShell did not initially expose Cargo because Rust was absent; rustup was installed with `--no-modify-path`. New shells may need `%USERPROFILE%\.cargo\bin` added explicitly for the session or user environment.
- Intel Iris Xe reports only 128 MiB dedicated video memory but about 8 GiB shared graphics memory. Do not treat WMI's `AdapterRAM` value as reliable VRAM capacity for an integrated GPU.
- D3D12 feature level 12_1 and Vulkan 1.4 are both available. This does not create a need for the Vulkan SDK: the runtime/driver is distinct from developer SDK tooling.
- Codex CLI `0.154.0` discovers repository skills under `.agents/skills`, not a guessed legacy project path. Repository instructions that should always apply belong in `AGENTS.md`; create a skill only for a reusable triggered workflow.
- Agent runtimes do not share discovery paths. Claude Code loads project instructions from `CLAUDE.md`/`CLAUDE.local.md` and repository skills from `.claude/skills`, and does not read `AGENTS.md`; it references that filename only in its Codex-configuration importer. Keeping the constitution in `AGENTS.md` with a thin `CLAUDE.md` pointer avoids two drifting copies of repository law.
- The source transcript contains research claims tied to its date and several community links. Preserve them as leads; re-verify time-sensitive facts before making product or dependency decisions.
- `wgpu 30` surface presentation uses `CurrentSurfaceTexture` plus `Queue::present`; older tutorial code that calls `SurfaceTexture::present` does not match this API. Keep examples pinned to the selected version.
- A window-owned `Arc<Window>` permits a sound `'static` surface lifetime without transmute or other lifetime hacks. Window creation still belongs in `ApplicationHandler::resumed` through the active event loop.
- On the audited host, the intentionally D3D12-only M1 build selected Intel Iris Xe, `Bgra8UnormSrgb`, `Fifo`, and `Opaque`. These are observed capabilities, not portable requirements; deterministic selection helpers retain fallbacks.
- Zero-sized windows must suspend surface configuration/rendering, and focus loss must clear input state. Both are explicit lifecycle behavior rather than exceptional failures.
- `ControlFlow::Wait` alone does not prevent idle work when `RedrawRequested` unconditionally queues another redraw. The render result must distinguish retry from suspension, stop the redraw chain for zero-size/occluded surfaces, and explicitly request redraw on restoration.
- For the dense M2 `32³` reference chunk, `VoxelId(u16)` occupies exactly 65,536 logical payload bytes. The exposed-face checkerboard worst case would emit 98,304 quads and 393,216 vertices, so `u16` indices are insufficient even though ordinary fixtures are much smaller; the reference mesh therefore uses `u32` indices.
- Keep the diagnostic CPU mesh richer than its current GPU layout: M2 retains normals/faces/IDs headlessly (17,952 bytes for the fixture), while the client adapter uploads only position/color plus indices (15,840 bytes). This preserves renderer independence and avoids making `VoxelId` or the voxel crate own presentation material data.
- Signed voxel partitioning must use Euclidean division: with edge 32, world `-1` is chunk `-1`/local `31`, while `-32` is chunk `-1`/local `0`. Truncating division produces invalid negative locals. An `i64` world coordinate can exceed the range representable by an `i32` chunk coordinate, so reverse conversion remains fallible.
- Seam correctness does not require a world-map dependency in the mesher. A borrowed center-plus-six-neighbors view is sufficient for exposed faces, but availability must remain explicit: known AIR, known solid, and missing data have different meanings. `Expose` is valid for a finite diagnostic boundary; `RequireKnown` prevents accidental unloaded-as-air behavior.
- Chunk-local CPU vertices plus a renderer-owned model translation preserve coordinate precision and dependency direction for the M3A proof. The current one-bind-group-per-chunk path demonstrates the boundary only and should not be mistaken for a scalable streaming/batching design.
- On the audited Windows host, MSVC linking can transiently fail with `LNK1104` when `cargo nextest` immediately follows another Cargo gate, even when the gates were launched sequentially. In the observed recurrence no project, Cargo, or rustc process held the named executables and the files were absent; rerunning `cargo nextest run --workspace` alone passed all 34 tests. Treat an isolated retry as diagnosis, not permission to ignore a repeated failure.
- Detached exposed-face meshing needs only the center chunk and one voxel-thick axial slabs. At edge 32 this is at most 76 KiB versus 448 KiB for seven full chunks; the owned and borrowed samplers can share one geometry loop and produce byte-for-byte identical topology.
- A coordinate alone is insufficient asynchronous identity after eviction/re-entry. A runtime-global, never-reused request token closes the ABA case, while content and mesh generations validate changes within the same incarnation. Hard-cap reservations must follow that token until every load result, including stale and `KnownAbsent`, releases it.
- Retention must cover the dependency halo (`retention_radius >= render_radius + dependency_halo`); otherwise dependency records are created and retired in the same demand update. Validate with `checked_add` and a typed error rather than trusting defaults.
- Camera-to-voxel mapping must use `floor`. `f32 as i64` truncates toward zero, so `-0.001` would land in chunk `0` instead of chunk `-1`, disagreeing with the Euclidean split. Convert through `f64::floor`, range-check against `[-2^63, 2^63)` explicitly, and reject non-finite input instead of letting `as` saturate.
- With one worker and eviction finalization running before dispatch, an eviction backlog cannot produce a hard-cap block: each poll frees at least one slot before reserving at most one. The cap still holds because retired payloads are counted. Test the invariant `resident + reserved <= cap` at every poll rather than expecting a block counter to move.
- Worker-timed tests need a real sleep between polls. Two thousand `yield_now` iterations completed before the worker thread had even woken on the audited Windows host; the existing 50 µs sleep pattern is the working one.
- `assert_eq!` cannot compare values containing `NaN`; use `matches!` with a bit-pattern guard when a test needs to prove that `NaN` was reported back.
- A source-confirmed absent chunk inside render demand must not be labelled "waiting for neighbors"; it will never mesh. Only `LoadQueued`/`Loading` render chunks are waiting. The first M3B2 client run showed nine permanently waiting chunks until that distinction was made.
- Keep "is this drawable" separate from "has its memory been released". Deactivating a GPU mesh is a per-frame correctness decision and is never budgeted; freeing its buffers is budgeted. Empty meshes hold no buffers and should bypass the upload budget so that air layers do not consume upload slots.
- A minimal trait with exactly one production implementor and one in-memory test double is enough to test frame orchestration headlessly. Keep it to the methods the orchestrator calls.
- An agent can perform the Windows interactive smoke itself: start the release client with stderr redirected, inject input with `keybd_event`/`mouse_event` (`winit` receives injected raw mouse motion), drive `MoveWindow`/`ShowWindow` for resize/minimize/restore/focus loss, capture the client area with `Graphics.CopyFromScreen`, and read the PNGs. Pitch the camera down first, otherwise every capture is sky; a `System.Diagnostics.Process` started from `ProcessStartInfo` reports the exit code reliably where `Start-Process -PassThru` did not.
- `sed` back-references stop at `\9`; `\10` is `\1` followed by `0`. Summarize wide `key=value` logs with a small Python script instead.
- An edge-generic voxel grid fits stable Rust without `generic_const_exprs`: keep cells in a heap slice sized at runtime (`vec![AIR; EDGE * EDGE * EDGE]`), give `EDGE` a default (`FaceSlab<const EDGE: usize = CHUNK_EDGE>`) so existing call sites keep compiling, and write conversions between concrete edges (`DenseGrid<32> -> DenseGrid<16>`) as explicit methods instead of a generic `EDGE / factor` type. Type aliases (`Chunk = DenseGrid<32>`) preserve associated-function calls such as `Chunk::empty()`.
- Mixed-resolution seams need no second mesher: encode the rule in the owned slabs. The fine side samples the coarse block occupancy expanded to its own resolution; the coarse side gets `known_air` toward a fine neighbor so it always emits. The single exposed-face loop then produces exactly one face per seam location or none.
- A seam test oracle must use the same orientation convention as the slab constructors (`face` is the direction from the center; the constructor selects the neighbor's touching layers). Writing `face.opposite()` in the oracle silently tested the far layer and failed both mixed-seam tests until corrected.
- LOD history must live on the record, not in the demand sets: keeping the previous level while a chunk is retained is what makes the one-chunk transition band free of ping-pong, and losing it on eviction is what keeps re-entry deterministic.
- A coarse seam face may be suppressed only when the fine seam layer covers it completely (4 of 4 cells); with partial coverage the whole coarse quad must stay, accepting overdraw behind fine solids, because subdividing the quad or suppressing it would open a crack. Encode the mask as its own slab constructor so it is never confused with source-confirmed absence.
- Measured on the audited host, deriving `Lod1` inputs (center downsample plus slabs) costs about 65 µs mean / 205 µs max per job in the orchestration path, at most once per frame; that is small against the 1 ms integration rail, so it stays out of the worker. The number, not the intuition, decides.
- When a test compares coordinates across a seam, compare only the seam-tangential axes; the normal axis differs by construction (touching layer vs seam layer). Writing the full-tuple comparison produced a false failure.
- A coarse level saves resident bytes but a spatial band charges every crossing: on the M3C2 path the 57% GPU-byte saving came with 74% more upload bytes and 41% more CPU mesh time, driven by 618 level swaps. Measure LOD on a moving camera, not a static one, and count swaps and re-uploads next to bytes.
- `tracing_subscriber::fmt` writes to stdout; a benchmark harness that redirects only stderr captures nothing. Redirect both, and never filter the console with `grep` before the log is saved.
- Injected keyboard input reaches only the foreground window. A benchmark harness must restore and re-assert focus before each input (restore if iconic, tap ALT, `SetForegroundWindow`, verify) and declare the run invalid if focus cannot be held; `cpu_evictions = 0` on a traversal path is the tell-tale of a run that never moved.
- A gap counter that only tracks chunks which were drawn before cannot see the worst hole: entrants that never appeared. The first transition model reported zero gaps while the floor was missing in a band for four seconds; a second counter (render-demand chunks whose replacement is ready but not drawn) and burst screenshots every 300 ms assembled into contact sheets exposed it. Instrument "never drawn" separately from "stopped drawing".
- Atomic transition groups must join only across a seam that actually changes (a drawn side's level or its contract toward the other face). Joining every adjacent dirty pair once one side is drawn chains the frontier to the moving `Lod0` ring, and continuous diagonal movement re-dirties that ring (one chunk crossing per axis every ≈1.35 s at 12 voxels/s) faster than it can mesh and stage, so the group never commits. The symptom read like a saving (fewer uploads and mesh jobs); it was starvation.
- Keeping an old mesh drawn through a level change is safe exactly when the drawn set stays mutually coherent: every drawn pair whose seam changes switches in the same update. Toward an undrawn neighbor the drawn contract may lag only while the drawn chunk's own replacement toward that face is pending; a checker that demands more than that flags legitimate retention, and one that demands less would miss a mixed seam.
- Upload and mesh-job counts alone cannot judge an LOD transition policy. A “gap” counter sees previously drawn geometry; `ready_undrawn` sees known non-empty geometry that has not appeared. Split the latter into upload wait, transition blocking, and a hard committed/bridge mismatch so a non-zero value is explained rather than declared benign. M3C's honest result is “no mixed seam or previously drawn blink, but bounded frontier deficits remain,” not “no holes.”
- Screenshot capture with `Graphics.CopyFromScreen` stalls the captured process (frame time rose from 16.7 ms to ≈41 ms during burst capture), so burst runs are for finding holes, not for timing numbers; take the timing numbers from a run with the normal capture cadence.
- Vertical-tab escapes survive a Python heredoc on this host: writing `"$env:TEMP\v..."` from a Bash heredoc produced a literal `\v` byte in the PowerShell script. Write scripts with the file tool or edit lines with PowerShell, and check the bytes when a path looks truncated.
- An atomic commit across runtime and presentation needs a proof against intervening mutation, not “both checks happen close together.” Hold the runtime's exclusive mutable borrow from its whole-group preflight through the presentation's all-or-nothing callback and CPU commit; reject empty/duplicate groups before invoking the callback; update bridge bookkeeping only after success.
- Memory high-water must be sampled at mutation boundaries, not merely once per frame/update. Staging and commit can happen in one update, so an end sample misses the old committed plus new staged overlap. An independent presentation-side mutation oracle caught this and moved the banded chunk-mesh result from 9,800,128 to 10,053,696 bytes. Name the accounting boundary: chunk meshes are not total GPU memory.
- The per-chunk-uniform diagnostic pattern does not scale to per-chunk *debug* geometry: one uniform buffer, one bind group, and one draw per box costs 26–65 ms per frame at 637 boxes on an integrated GPU, against 16.67 ms with the view off. That is acceptable for an opt-in view and is the measurement to quote when someone proposes instancing.
- A debug view of streaming state must read the runtime's own states rather than re-derive them from what the renderer happens to hold; one query returning residency, mesh state, level, and pending flags per tracked record keeps the renderer free of streaming logic and makes the whole mapping testable without a GPU.
- Wireframe debug colors need contrast against both the dark sky and the lit floor. The first residency capture was visually empty because the most common states were dark greys and blues; every state color is now at least 0.45 in one channel, which is a design constraint, not a taste preference.
- Screen capture with `Graphics.CopyFromScreen` stalls the captured process, so a frame-time A/B of a debug view must run with no captures at all: the capture-heavy smoke reported 69 ms frames where the clean run reported 26 ms for the same view.
- Prove the precondition before optimizing a lifecycle. The restage release-before-allocate fix is only safe because the bridge restages a coordinate solely when its staged stamp is no longer the target, and such a replacement can never be committed. That chain, not intuition, is what makes dropping GPU buffers before allocating their successor correct.
- A code path can be correct, reachable, and still never exercised by the benchmark. Restaging needs a replacement to become CPU-ready in the same update that invalidated it, and `discard_obsolete_staging` almost always wins that race, so `restaged = 0` in every driven run. Cover such a path with unit tests and say plainly that the benchmark does not reach it, instead of assuming a measurement proved anything about it.
- Before attributing a metric change to a code change, measure the unchanged binary on the same path. The banded chunk-mesh peak varied between runs, so a documented single sample looked like a regression until the audited build reproduced the same spread. A high-water number from a time-based driven path is a draw from a distribution; record the range and the run, never one figure as a constant.
- A cache and a save are different problems and the difference has to be enforced, not just stated. Making every entry reproducible from the source is what lets corruption handling be trivial: reject, delete, ask the source, republish. The moment an entry holds something unreproducible, that whole policy becomes data loss and needs durability, migration, and transactions instead.
- A version/fingerprint/coordinate key isolates source identities, but “write-once” is not a portable rename guarantee. Windows normally refuses a target that appeared during the race; Unix may atomically replace it. Make concurrent values semantically equivalent, test that readers get one complete value, and document that correctness does not depend on which publisher wins.
- Omitting `fsync` is valid only because this cache is discardable. Same-directory temp-and-rename gives normal-operation atomic visibility, not power-loss durability; after a crash, missing or checksummed-invalid data regenerates. The same policy would be data loss for authoritative persistence.
- A locked hash of constants does not observe generator code. For the finite diagnostic source, hash the actual canonical outputs over its whole declared domain plus an absent shell in a test, include that locked behavioral signature in the cheap runtime fingerprint, and state the boundary: it is a tripwire, not source-code hashing or cryptographic identity.
- Recovery metrics must describe what completed. Deleting a rejected entry is not by itself a “repair,” and a delete failure cannot be hidden behind `unwrap_or(false)`: preserve the source result, count the failed cleanup separately, and expect the poison to be rejected again until cleanup succeeds.
- Measure a cache against the thing it replaces before believing in it. On the diagnostic fixture the cache is slower than no cache, because the source is a trivial generator and disk plus decode costs more than regeneration. The mechanism is still worth building and proving; the speedup claim is simply not available yet, and saying so is more useful than a flattering number.
- A compression result on an unrepresentative fixture is not a decision. Run-length beat raw by 169× on a corridor that is 97% air, and by every timing measure, yet raw stayed the default because its worst case is bounded at exactly 64 KiB while run-length's is 3× that. Implement both, measure both, and let the fixture's limits decide how much the measurement is allowed to conclude.
- A hard input-size limit does not require reserving that limit up front. The cache reader must cap hostile files, but preallocating its 196,657-byte maximum for every 48-byte absence or small RLE entry turned boundedness into avoidable allocator and memory-zeroing cost. Apply the limit at the reader and let storage grow with actual bytes.
- A heightmap cliff cannot show strata banded by depth. Whatever the gradient, a column exposes only as many voxels as the terrain drops next to it, which on anything walkable is fewer than the depth a second rock tone would start at, so every face renders one flat colour. Banding rock on world height instead gives every exposed face horizontal breaks and makes them line up across neighbouring columns. It was the single largest visual improvement in M4 and cost one changed argument.
- Classify terrain by the widths the configuration actually declares, not by a threshold on an interpolant. Landform was first decided by comparing a smoothstep result against `0.08`; retuning the valley wall silently moved every boundary and deleted a whole biome zone. Comparing the distance from the axis against `valley_floor_half_width` and `highland_onset` keeps the boundaries where the art controls say they are.
- Make a spacing rule a theorem instead of a hope. Jittering a placement lattice by at most half the slack between the lattice spacing and the minimum spacing means two neighbouring anchors can never come closer than the minimum, whatever the hash returns. The test then proves the property rather than sampling for a counterexample.
- A camera pose is a fixture and needs the same tests as content. Three of six M4 poses were written from arithmetic before the terrain existed and put the camera inside a hillside or inside a tree canopy, which produced frames of backface-culled sky and flat green. Asserting ground clearance and that no plant occupies the camera voxel turned a re-shoot into a failing test.
- A shading cue you cannot see is not evidence that it works. The first water captures had the sun behind the camera, where a specular highlight on a horizontal surface cannot appear at all, and read as flat grey. Framing the shot along the sun's reflected direction is what made water look like water; the shader had been right the whole time.
- Re-measure an accepted default when the content changes, not when the code does. Raw was the right cache default for a fixture that was 97% air; real terrain is layered, so runs are long, and the same eighty-one chunks fell from 4,132,656 bytes to 107,904 while encoding six times faster. Nothing in the cache changed. Only the thing being cached did.
- One job per poll bounds a pipeline at the frame rate, not at the worker's speed. The M4 golden profile needs about 3,500 jobs and settles in a minute at 60 Hz, which looks like slow generation and is not: generation is a millisecond per chunk. Before optimising a producer, check how often anything asks it for work.

- A rotation convention has to be checked against the camera's, not against itself. `Quat::from_rotation_y(yaw)` turns `-Z` toward `-X` while the camera's forward at the same yaw is `+X`, so the character walked backwards along its whole course and every headless test passed: they all used the same wrong convention and agreed with each other. Only a capture disagreed. Pin a facing convention with tests at `0`, `±π/2`, `π` and one arbitrary angle, and add one test that a moving body moves the way it faces.
- Shadow acne on a small object is a resolution problem before it is a bias problem. A `2048²` map over a `112`-unit radius is `0.109` world units per texel — larger than a character voxel — so a character's own depth cannot separate from its neighbours' and the chest self-shadowed in stripes. Front-face culling in the shadow pass removes it completely, at the documented cost that the character casts no shadow on itself. Chunks already did this; the character was the only pass that did not.
- Where a subject stands is part of the capture, and it needs the same scanning a camera pose does. The first portrait frames came back with the legs behind an M4 shrub, because the stand point had been chosen for the walk and there was a bush four world units in front of it — exactly where the front camera goes. Scan for the stand: dry, level as far as the nearest camera, clear of vegetation further than the furthest camera, and open enough that nothing behind the subject is higher than the camera in front of it.
- Point the subject at the sun before blaming the palette. With a key light at azimuth `-38°` a character facing `+X` turns its whole front away from it, and the first portraits were a correctly lit scene containing a subject in its own shade. Nothing about the materials was wrong. A stand point owns a facing for the same reason a camera pose owns a yaw.
- "Wider reads as a torso" is backwards for a blocky body. A chest two voxels wider than the pelvis was authored on that theory, and in the game it overhung the waist as a ledge, swallowed the top of each sleeve, and let daylight through the notch between ledge, waist and arm. A torso reads because the arms stand clear of a straight chest.
- An invariant can be correct and still cost a visible voxel, and the cheapest repair is often a material rule rather than geometry. Closing the shoulder means putting the innermost column of the upper arm inside the chest, which made the sleeve show two voxels while the forearm below it showed three: the arm appeared to grow at the elbow. Painting the chest column that hides it with the sleeve's colour gives the shoulder its third voxel back and moved no geometry at all.
- Character scale is a relationship to the world, not a number in a table. At `16` voxels per world unit the humanoid was `1.75` units with a leg of `0.6875`: shorter than the undergrowth it walked through, and with a whole leg shorter than one terrain voxel, so a single terrace of its own world was a step it physically could not take. One capture and one arithmetic check said the same thing. Fixing the ratio also means making the gait thresholds relative to leg length, or the same body at a new size walks at the wrong cadence.
- A diagnostic course that runs once has always finished by the time a capture fires. The harness waits for the world to stream — seventy-five seconds here — and the course was forty-six, so every capture of a walk was a capture of a character standing at the end of one. Close the course into a loop whose last leg returns to the start position and facing, then sample it modulo its own duration: the wrap is continuous and any settle time lands somewhere in the walk.
- PowerShell is DPI-unaware by default, and on a scaled desktop that silently corrupts every screen rectangle it asks for. At 1920x1080 physical and 125%, an unaware process sees 1536x864 logical pixels, so `GetClientRect`, `ClientToScreen` and `CopyFromScreen` disagree and captures come back stretched, cropped, or containing the desktop. Call `SetProcessDPIAware()` before touching `System.Drawing` or `System.Windows.Forms`, then verify the saved size against the real client size rather than trusting it.
- Two places that compute the same byte figure will drift, so make one of them print what the other uploads. The probe reported a 64-byte transform per part while the renderer uploaded an 80-byte uniform — a matrix plus a parameter vector — and the milestone document would have carried the wrong number into its performance section. Log the figure from the runtime as well and compare the two, rather than deriving it twice.
- Name the mechanism before writing the fix, and A/B the fix before keeping it. A dashed dark line at a flexed knee looked exactly like z-fighting between the coplanar side planes that a joint overlap creates, so a per-part depth tie-break was added to break the tie. Captured with the bias on and off, the two frames were identical: the line is the parent limb's *downward-facing* end cap emerging through the child along the intersection the flex opens, about a tenth of a voxel wide and dark because it faces away from the sun. It is a consequence of rigid parts, not of depth precision, and the tie-break was removed rather than shipped as an unverified guard against an artifact this host does not produce.
- A frozen frame cannot tell you whether a walk walks. Eight phases of a gait, captured one run each, showed a plausible stride, contralateral arms and clean contact — and the walk was inverted: the hip swing was half a cycle out of step with the stance window, so the planted foot swept *forward* through stance and the character moved like a treadmill. What found it was a headless measurement of how far a planted ankle wanders across one stance: `1.39` world units against a stride of `0.99`. Write that measurement before tuning anything, because it is the only oracle that distinguishes a walk from a slide.
- Stride, duty factor and pelvis drop are one decision, and a gait that treats them as three independent amplitudes cannot be fixed by tuning. A planted foot must give back `duty * 2 * stride` of ground relative to its hip over one stance, so half of that is how far in front of the hip it lands — and a leg standing straight has no horizontal reach whatsoever, because the hip-to-ground distance *is* the leg. Unless the pelvis lowers, the foot the stride asks for is not a place the leg can reach, and the solver silently clamps. Deriving the three together took a planted ankle from `1.39` world units of wander to `0.04`.
- A sinusoid cannot cancel constant motion for more than half a cycle. Whatever its amplitude, a cosine hip turns around before a stance of duty `0.56` ends, so the second part of every stance slides. A straight line in foot offset during stance, rejoined by a cubic with matching slope through swing, costs about fifteen lines and removes the whole class of error while staying C1.
- Drive a dependent joint from the thing it depends on, not from a second copy of the same curve. The arms were `-arm_swing * cos(phase)` against a leg that was no longer a cosine, and the two crossed zero three hundredths of a cycle apart — a narrow window where an arm and the leg beside it swung together. Feeding the arm the leg's own offset makes the opposition exact by construction rather than nearly true, and deletes the test's tolerance along with the bug.
- A volume that contains a body is not a volume that decides a hit. M5's whole-body capsule holds every voxel of the rest pose, arms included, so it came out `0.83` wide on a body `0.50` through the chest and reached from half a unit below the ground to above the crown — and combat swept the blade against it, registering hits with the sword still raised over the shoulder and its tip in the air above the head. Two volumes, two jobs: keep the fat one for stopping bodies interpenetrating, and derive a narrow one for deciding damage.
- A single upright capsule cannot hold a walking humanoid's legs, and refitting it every tick does not help. A striding body throws a thigh `0.35` world units clear of any capsule fitted to it standing still and a shin `0.30`; refitting to the current pose just makes the barrel time-varying, because the width is the stride's and not the fit's. The torso column — pelvis, spine, chest, head — is the widest core that stays the width of the body. Everything that swings goes outside the volume, and that is a limitation to assert and document rather than to engineer around.
- A capsule fitted to a box has to choose which way to be wrong. Solving the cap centres so every corner is contained is exact, and pushes the top of the capsule up to a radius above the crown — which is how a hit lands in the air over a head. Clamping the band to the core's own extent keeps the volume inside the body, and lets rim corners poke out. Measure both: here the clamp left a thigh corner `0.12` outside, the solve clears a cubic head by about `0.10`, and a volume the body can leave is worse than one that clears the head, because the first drops hits the player watched land.
- Check the units of a geometry helper before building an analysis on it. `closest_points` returns a **squared** distance, says so in its own documentation, and a diagnostic table printed it as a distance — so every gap it reported was wrong by a square. The same table computed a bearing as `(-x).atan2(-y)` where the engine uses `x.atan2(-y)`, mirroring the column and making a swing that connected look like one aimed forty-one degrees wide. Delegate to the engine's own function instead of writing the arithmetic twice, and make the tool's numbers agree with a second measurement before believing either.
- A frozen frame cannot show an effect that an event causes, unless the event's own tick runs where something is listening. The moment search replays a script before the frame loop exists, so the tick that produced a hit published its events into nothing: the first frozen capture of an impact came back with zero chips and zero camera strikes, and nothing was wrong with either. Find *which* tick in one pass, then replay to the tick before it and hand the rest to the frame loop, so the moment's own tick goes through the path a played tick takes.
- A fixed camera pose cannot frame a moment. A named pose is an offset from a place, and a fight is wherever it drifted to by the tick a moment happens on — the `defeat` capture caught both bodies in line with a camera that looks along `x`, and came back showing one figure standing alone. Reinterpret the pose's offset in the fight's own frame — across the line between the bodies, above the ground, along that line from the midpoint — and every moment is framed the same way however it got there, which is what makes two captures comparable at all.
- Biasing a spread into a half-space cancels the directions that oppose it. Twelve unit directions plus `away * 0.9` left the four pointing back at the attacker with almost no length, so they normalised to noise and the burst left as one clump. Reflecting about the plane perpendicular to the blow keeps every direction a unit vector and keeps all twelve distinct, while still sending none of them backwards.
- A blind driver aims no better than it walks, so do not read a design defect out of its miss rate. A scripted key pattern landed one swing in thirteen, which looked like an unplayable attack and was not: standing a passive body at a bearing and swinging shows the arc forgives roughly `-45°` to `+14°` at contact range, and a swing aimed at the body connects at every range the attack reaches. Measure the window before adding an aim assist to a problem the harness invented.
- The real-time audio contract is a property of the code or it is nothing. A callback that runs under a millisecond deadline may not allocate, lock, log or panic, and `std::sync::mpsc` is not documented to be allocation-free — a channel that *probably* does not allocate is not a real-time channel. A single-producer single-consumer ring of atomics needs no `unsafe`, which matters in a workspace that forbids it, and makes the claim checkable rather than hopeful. Everything the callback wants to say becomes an atomic the game thread reads on its own time.
- Count the events and count the sounds, and make them the same number. A scripted fight recorded 15 player hits, 15 adversary hits, 7 player whiffs and 16 adversary whiffs, and the device started exactly 53 voices: no sound invented, none lost, and one line of evidence that presentation is driven by the rules rather than guessing alongside them.
- An audio test can prove everything except whether it sounds right. Amplitude, envelope, decay, band energy, voice limits, clipping, determinism and silence-on-idle are all assertions; "this reads as an impact" is not one. Render a deterministic offline `.wav` so a person can decide, and say plainly in the milestone that the judgement has not been made yet rather than implying the measurements covered it.
- A defeated body needs a pose, not just a state. `Defeated` reused the carry pose, so the last frame of a fight showed the loser standing with its sword out, indistinguishable from a body about to swing. The fix is four keys and no new machinery — knees give, torso folds, blade drops — and the window it eases over has to be the whole window: easing across a quarter of it finished the sag in six ticks of the twenty-four the constant promised, and read as a snap.

- A smoothed presentation value must never decide an authoritative rule, and the way to find out that it does is arithmetic rather than a playtest. `CharacterState::base_height` is the filtered height the pelvis follows; movement legality compared a candidate step against it. At `tau = 0.12 s` and 120 Hz the filter closes 6.71% of its gap per tick, so a body climbing at gradient `g` at `3.4` u/s carries a lag of about `0.42 g` world units — and with `max_step_up` exactly one voxel, *any* lag makes a legal step illegal. The same step was legal standing still and illegal while walking. M6 never saw it because its arena is asserted exactly level, and the only test that covered a step built the state with the pelvis already settled.
- A rule that an audit also needs must return *why*, not just whether. Recomputing "which condition failed" outside the rule is a second implementation of the rule, and it is the copy that drifts. One `check_move` returning `Result<(), MoveBlockReason>`, with the order of the checks documented as part of the contract, lets an offline reachability audit attribute every barrier to a cause using the game's own function.
- Two optional trait references of the same shape, passed positionally, swap places silently. `ground` and `legality` are both `Option<&dyn _>` and answer completely different questions; a named parameter object with three constructors makes each of sixty-four call sites say which it meant.
- "Where a body starts" is not tuning. Putting an arena centre in the combat tuning made one value mean the arena's middle, the enemy's site, the player's respawn and the reset point at once — readable for a duel in a disc, and meaningless the moment the two bodies start a route apart rather than six units apart.
- A continuous field relation and the voxels a generator writes from it are different predicates, and the difference is a visible band rather than a rounding detail. Water fills a cell when `world_y > surface_y && world_y <= water_surface_y`, so a water voxel exists exactly when `water_surface_y() > surface_y()`. The continuous `water_surface > height` says yes for columns where both floor to the same voxel and the viewer sees dry ground. Name the voxel predicate once, in the crate that writes the voxels, and let generation, traversal and the invariant all ask that one function.
- An offline audit over a cached copy of the world is a second world unless something asserts otherwise. The cache exists for cost — five million candidate steps against 640,000 field samples — and a test comparing it to the production adapters at every column centre of several chunks is what keeps it a cache instead of a fork.
- A settled-column breadth-first search is a topological claim, not a runtime one. The proof that a route is walkable is simulating it tick by tick through the authoritative loop with the real filters running; everything else is an upper bound. Say which one a number is, every time.
- A body held against a barrier **slides**; it does not block. `try_move` refuses the whole proposal, refuses one axis, accepts the other, and returns `slid`. A log watching only `blocked_moves` cannot tell a free walk from a body pinned at a waterline travelling twenty-three units along the shore, which is exactly what the first water run reported: zero blocked moves for the entire time it was held.
- Put the camera's position in the report before you need it. Two shoreline captures came back with the lower half of the frame filled by flat ground and no player in it, and working out why meant reasoning backwards from pixels to a camera. Three numbers in the existing report line answered it in the next run: the camera was `0.5` above its own ground on a bank the body had already descended, so at the follow pitch its sightline met the ground two units out and the body was six away.
- A fix that does not move the thing it is meant to move is not a fix. A camera clamp against the ground under the body was written for the shoreline case, measured at `0.05` world units of correction, and reverted. The finding was recorded instead.
- Whether an exact partition of wall time hits the catch-up cap depends on how the spare nanoseconds are distributed, not only on the frame rate. Twenty seconds at thirty hertz is exactly `MAX_TICKS_PER_FRAME` ticks a frame; front-loading the remainder never reaches a fifth tick, spreading it through the run does. Both are exact. A probe that measured "no capped frames at 30 Hz" measured its own distribution.
- A blind driver aims no better than it walks, and a driver reading a five-second report line aims at where the body *was*. Eleven swings and zero hits from a scripted fight loop is a statement about the harness, and M6 had already settled the underlying question by standing a passive body at a bearing and swinging. Say which of the two a miss rate is measuring before concluding anything about the fight.
- The shortest legal route around an obstacle is evidence about the obstacle. The derived route never comes within six columns of the river, so the `water-edge` checkpoint it defines is never emitted — the rules route around water without being told to, and the absence of the checkpoint is what says so.
- Predictions written down before a measurement are worth keeping even when they are wrong, and especially then. M7's design predicted the valley wall's `1.73` rise-over-run might make the highland unreachable to a body limited to one-voxel steps. It is reachable, from 22 steps away, and 243,333 highland columns are in the reachable set. What the audit *did* find was different and would not have been guessed: the region splits into two large components and the session starts in the smaller one.
- A playtest can pass its gate and still not reach the content behind it. The M7 owner walked the region, judged the traversal a pass, and never found the single adversary standing in it — so exploration-to-combat, a victory and the continuation past one stayed technical evidence. Traversability and discoverability are separate properties, and a milestone that proves the first proves nothing about the second. Say which one a session actually exercised.
- An owner observation is not a work item. "Locomotion feels somewhat stiff and raw, but is acceptable" is worth exactly as much as it says: it is recorded, nothing was tuned in response, and it becomes evidence for whatever milestone takes movement feel as its subject. Acting on it inside the branch that heard it would have turned a judgement into an unreviewed change.
- A log line that reports its input instead of its outcome will eventually be quoted as a fact. `encounter frozen at a named moment` printed the moment's tick and nothing else, so `moment:confirmed-hit` and `moment:confirmed-hit+6` both said `tick=499` while the second was actually frozen at `505` — and a milestone document duly recorded that both freeze at the same tick. The line now prints `tick`, `offset` and `frozen_at`. When a value is computed from another, log both; a reader cannot subtract what is not there.
- Write the assumption as a test before writing it into a document. Branch QA asserted that the water veto answers the same everywhere inside a column, which seemed too obvious to check, and it failed at `(31, 3)` in seconds: `TerrainWalkability` samples the terrain field continuously, exactly as `TerrainGround` does. The test that survived says something better and true — the veto disagrees with itself only in a one-column band along the drawn waterline — and the audit's status as an upper bound is now a measured property rather than a caveat.
- An oracle must not share code with the thing it judges. `the_adversary_stands_somewhere_the_region_allows_a_fight` asks the placement predicates about the placement they produced, over the grid they walked; it cannot notice the grid being wrong. The replacement generates the chunks, reads the topmost ground voxel of every column in the disc, and re-derives level, dry, clear and far from the voxels alone — and bounds the distance with a Chebyshev lower bound, which needs no graph at all. Same answer, independent derivation; only the second one is evidence.
- A closed loop cannot be tighter than the interval of the thing it reads. The client reports `combat state` every five seconds, so a player defeat, its `2.5` s hold and the reset all fit between two reports and a polling loop sampling four times a second saw the health go from `6` to `96` with nothing in between. Twice. The fix was not a faster poll but a different instrument: capture continuously through the window and read the frames afterwards. Know the sample rate of the signal before designing the loop that watches it.
- A defeat pose that keeps the body upright is still a defeat pose. Reviewing captures of a defeated player, the first reading was that the pose had not been applied — the body was standing. It had: `defeated_pose` is a slump, pitching spine, chest and head forward and dropping the pelvis, not a topple. Put the frames side by side at the same crop before calling a pose missing; one frame in isolation is not a comparison.

- A property test can be stricter than its own name, and nobody notices until the world gains its first obstacle. `no_step_of_the_route_cuts_a_corner_between_two_blocked_columns` flagged a diagonal whenever **either** shoulder was unstandable, while its name, its comment and the bug it is about all say **two**. M7 passed it because the region had no obstacles to brush. The first landmark produced a route that passes one corner, the runtime walks it happily under ADR-0008's destination-only rule, and the honest fix was to make the assertion say what the name says and count the brushes separately.
- A gate's tallest column is the lintel over its opening, so "the crown column" is not a wall. A test that asked whether a body may stand at each landmark's crown passed for the spire and the broken monolith and failed for the gate — correctly, because the ground under an opening is exactly the ground a gate exists to be walked through. The witness a solidity test wants is a column filled from the base course up.
- Erosion that removes voxels in place invents floating ones. Weathering a spire by deleting outer-ring cells left a corner voxel with nothing under it, because the cell it rested on had already gone. Eroding top-down and refusing to remove a cell that carries another is three lines and removes the whole class.
- A silhouette class can be its own mirror. A spire with `lean = 0` is symmetric, so "no two landmarks look alike" silently became "these two are reflections". Making the lean always `±1` and rejecting `0` in validation is cheaper than any de-duplication rule.
- A ratio is only as good as the population it is measured over. The gate's "second mass" check compared the shortest column against the tallest and kept failing at `0.77`, because the columns under the opening carry only the lintel. The measure that means what it says is the second tallest **connected component of grounded columns**.
- Reusing one candidate set for two different searches is a false economy that changes the answer, not the cost. Drawing the third landmark from the ring generated around the overlook saved 200 ms and moved it from 184 units away to a marginal site with exactly the minimum visible silhouette — because the sites that reveal well lie *beyond* the first pair, outside that ring. Searching around the revealer is the question being asked; the candidate set has to match it.
- Measure the cost before choosing where to cache, and check how the tests actually run. The landmark plan costs `1.1 s` per world in debug, which looked like an argument for memoising it — until the execution model settled it: `cargo nextest` runs **one process per test**, so no in-process cache can help a suite at all. What a cache does help is one process building the same world three times, which the client was doing, and the fix there is one explicit `build()` that shares an `Arc`, not a global.
- A placement rule may not consult the movement rules, but it may still ask a question about the world that correlates with them. "No water on the straight line between the viewer and the site" is a composition rule — a landmark you are invited to walk to should not have a river across the invitation — and it needs nothing from `veldwake-combat`. It pruned half the candidate sites, made the derivation twice as fast, and left real reachability where it belongs: validated afterwards, by the client, with the game's own rule.
- The capture overruled the design intuition, which is why the capture exists. "The whole silhouette should fit inside the default frame" sounds obviously right and produced a worse game: at the distance it forces, the canopy leaves `8.3` visible voxels instead of `21.3`, and the shot is a sliver near the top edge instead of a tower rising out of the frame. Both compositions were built and photographed before choosing, and the rejected one is recorded in the code beside the rule it did not become.
- `cargo nextest` writes its summary to **stderr**. A background harness that pipes only stdout into `grep` reports an empty run and exits non-zero with nothing to read, which looks exactly like a crash.

- The smallest amount of deliberate-looking world content changed what a person did. Three generated stones, one family, no lore, no interior, no prop and no interface: the same owner who walked M7's region and found nothing noticed two of them, called them different destinations, picked one and walked to it. The lesson is not that landmarks work; it is that "nothing here means anything" was a content problem the whole time, and it took less content to fix than the discussion around it suggested.
- A silhouette class is named by the person looking at it, not by the compiler. The compiler built a Gate and the owner read it as a broken construction. Both readings are of the same voxels; what differs is that the lintel is above the frame from where the composition intends it to be seen. Two useful habits follow: state the class a person actually named, and look for the mechanism in the framing before concluding anything about the shape.
- "Simple but sufficient" is a complete answer, and treating it as a request for more work throws away the result. The owner passed the gate, said the structures were simple, and named the thing that would be worth improving eventually — a visual identity of its own rather than a familiar voxel-RPG one. Recording that as evidence for a later art-direction decision costs one paragraph; acting on it inside the branch that heard it would have turned a judgement into unreviewed scope.
- Count commits from the branch, not from the session. A report said the branch carried "two commits" because that session had created two; the branch was four ahead of `main` and three past its base, because the milestone plan had landed before the session started. State branch facts with `git rev-list --count`, and say which base a count is against.

- A constructor documented "infallible by construction" is only as true as the construction it names. `CompiledMonolith::new` relied on every caller using `from_seed`, which nothing enforced; a hand-built descriptor divided by zero on `band_period = 0` and compiled negative dimensions into an empty landmark. The validator that rejects both already existed one type away. When a comment says a precondition holds, ask what would happen if it did not, and then make the type say it.
- Build the baseline world the difference needs. The strongest proof that landmarks never replace terrain was not a careful reading of the writer; it was generating the same chunks twice — once with the composition and once with a world of the same identity composed without landmarks — and looking at every voxel that differed. An oracle you can build in twenty lines beats an argument you have to trust.
- An oracle that fails first is usually the oracle. Three of the first five QA tests failed, and all three were the test being stricter than the contract: a landmark may stand where its own reservation removed a plant, a neighbouring canopy may occupy the box a removed tree used to fill, and the plan checks water around the site centre rather than around the footprint. Write down the contract you think you are checking before deciding the implementation is wrong.
- A single quiet measurement is not a range. The derivation was recorded at `248`–`272` ms and re-measured at `316`–`409` ms on the same host with nothing else running; the work had not changed. Quote a range wide enough to have been observed, and say how many runs it came from.
- Count what is written, not what was compiled. The three landmarks hold `1,729` voxels and write `1,740`: the difference is foundation, which the compiled object never sees because the world adds it under the base course. Two numbers that sound like the same number are worth naming separately.
- A blind driver curves. Holding "forward" for a hundred units in the driven harness lands about eleven degrees off, because the follow camera re-derives its yaw from the camera-to-anchor vector each frame and the lateral offset rotates it slowly. A player corrects without noticing; a script walks past the thing it was aimed at, which is how three QA runs missed a fourteen-unit aggro radius.
- A reaction delay is bounded by the windup it reacts to, not by how fast or how short the response is. Combat Pressure asked whether a shorter sidestep would let an adversary react at `24`–`30` ticks. It could not: the player's swing winds up in `22` ticks, so a response that starts after `24` starts after the blade is live, and three dodges of `20`, `24` and `36` ticks at the same speed of about `7.3` u/s all escape nothing at `24`. Before tuning a reactive defence, put the reaction delay next to the windup it answers; if the delay is longer, no response is both fair and effective.
- Separation without conversion is either nothing or a stalemate. Evasion that opened distance made the owner's strategy draw rather than lose (four of six sixty-second stalemates), and lateral evasion changed nothing, because the adversary's only attack needs about `57` ticks from commit to contact while a whiffing player is free `41` ticks after its active window. Ask what converts a created opening before building the thing that creates it.
- Roles can be swapped instead of rules added. The rules are side-neutral, so the adversary's body evading the player's swing was measured by standing that body on the player side, where a dodge can already be requested, and giving the other side the player's body and attack. The measurement needed no production change at all, and it reproduced the scratch numbers exactly.
